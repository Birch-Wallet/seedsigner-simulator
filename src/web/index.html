SeedSigner Web Simulator

Never enter a real seed phrase. On Mainnet this page holds the real mainnet keys for whatever you give it, with no secure element under them: treat anything typed in as public.

i

Never treat this as secure. Not on a phone, and not on an airgapped laptop with the network unplugged. Making device firmware run in a browser took a great deal of custom wiring, any of which could have introduced a critical bug. Treat every key it shows as public and never enter a seed phrase you rely on.

This is device firmware, not a re-creation of it. The Python that runs on a SeedSigner runs here, under Pyodide (CPython compiled to WebAssembly). Nothing in the firmware is patched, and the release it is built from is rebuilt below.

Running stock SeedSigner 0.8.7, the firmware a plain SeedSigner runs.

What is in it

The upstream tree at the commit above, this repository's stand-ins for the hardware a browser does not have, and these pinned dependencies. Nothing else.

    Check it yourself: rebuild the zip · the same rebuild on a clean runner · tests · upstream's own tests · source

    Three things a browser cannot do, replaced from outside the firmware and never inside it:

    • Display: the device's own driver renders the frames; the page paints them at the panel's own size, 320×240 or 240×240, pixel for pixel.
    • Buttons: the worker is blocked inside the firmware's main loop, so keys cross on a SharedArrayBuffer.
    • Camera: your webcam. pyzbar has no WebAssembly build, so decoding happens in the browser and reaches the unmodified decoder unchanged.

    Driving it. Press the drawn buttons, or the keyboard: arrows move, Enter selects, 1 to 3 are the side buttons.

    Two devices. The switch under the device picks the hardware: the SeedSigner Plus with its 320×240 screen, or the original build on a Waveshare 1.3" hat at 240×240. Switching starts the firmware again.

    Recording it. Record saves an MP4 of the session, either the firmware's screen alone at its own size or the whole device. The video is made in this browser from the firmware's frames, not by filming the page, so the pointer is never in it, and nothing is uploaded anywhere.
